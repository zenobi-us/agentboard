# Review: Issue #56

## Scope

Reviewed the Bun Action Plugin implementations in:

- `pkgs/packages/agentboard-action-run-cmd/src/`
- `pkgs/packages/agentboard-action-worktree/src/`
- `apps/cli/src/services/`

The plugin descriptors, TypeBox schemas, runtime creation, action execution, health checks, retry state, and worktree behavior were already present in the branch from the Bun runtime work. This review kept the change isolated to the action packages.

## Findings

- `run-cmd` uses `sh -c`, rendered inputs, action environment variables, cwd handling, output caps, launch health checks, exit translation, and process-group cancellation.
- `worktree` uses plain `git worktree`, managed-worktree checks, clean switching, branch collision checks, desired-state convergence, and cancellation.
- `doctor` calls plugin health checks without creating action runtimes.
- Workspace loading creates one action runtime per configured action. Watch cycles reuse those runtimes.
- Fixed a cancellation race in `run-cmd`: an invocation cancelled after launch completion no longer starts a health-check probe.
- Fixed a worktree safety error: the repository root is not accepted as a managed worktree root.
- The standards review found no documented-standard violations.
- Windows process-group behavior remains limited by Bun. The existing implementation kills the direct child on Windows.
